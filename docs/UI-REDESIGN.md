# Перевірка актуального UI та налаштувань

Нові перевірки 2026-10-04 і screenshots: [REQUEST-FIXES.md](REQUEST-FIXES.md). Числа тестів нижче належать попередній ітерації.

## Результат

Графітово-білий мінімалістичний інтерфейс замінив попередній Liquid Glass. Одна шапка, центральний Фото/SDS switch, іконки історії/налаштувань/теми, форма зліва й справжній preview справа. Теми мають окремі кольорові токени; PNG/PDF не інвертуються і не тонуються.

| Вимога | Реалізація та перевірка |
|---|---|
| Темна та світла теми | `minimal.css`; theme toggle працює, світла тема збереглася після reload |
| Плавний switch і зміна інструмента | Ковзання 330 ms, коротка поява/зникнення робочих областей; стрілки клавіатури змінюють режим і фокус |
| Компактна сторінка | Без sidebar, hero, breadcrumb, декоративних підписів. Маски/номер, експорт, шаблон назви та перевірені назви — disclosure-блоки |
| Не губити роботу при переключенні | Обидва інструменти лишаються mounted. Два PNG-результати й введений список збереглися після переходу в SDS і назад |
| Маски | Модальне вікно перенесене в `document.body`, фон inert; Tab/Shift+Tab/Escape та повернення фокусу перевірені на 360 px |
| Постійні налаштування | Типова назва SDS, PDF, власні машини/маски та per-template HEX — серверні, не localStorage |
| Історія | Реальний SDS `UI_SDS` знайдено після reload, preview і кнопка завантаження доступні; строк зберігання 30 днів явно показаний |

## Реальні перевірки

- `pytest -q`: 19 passed, одне попередження Starlette про deprecated TestClient HTTP-клієнт.
- `npm run build`: TypeScript та production build успішні. CSS 28,18 kB, gzip 6,14 kB; зовнішні UI-шрифти не завантажуються.
- `npm --prefix frontend audit`: 0 vulnerabilities на момент перевірки.
- Фото/SDS у dark/light: viewport 360, 768, 1280, 1600 px — ширина документа не перевищує viewport. Налаштування/історія у двох темах: 360/1280 px; розгорнута форма додавання машини й шапка також перевірені на 320 px.
- SDS generation і PDF editor: головні дії видно на першому екрані 1280×720 у типовому компактному стані; у редактора нижній край кнопки Apply — 703,6 px. Відкриті додаткові поля, великі списки й повідомлення можуть збільшувати сторінку.
- Через Фото UI згенеровані `UI01 #4D778A` та `UI02 #A1382C`. Реальний ZIP збережено браузером; усередині два PNG та `generation-report.json` у `Asturcolor/Демо-шаблон/`.
- Через SDS UI створено `UI_SDS_SDS_Asturcolor_Seat_CANDY_WHITE_repaired_no_filter_mask.pdf`; результат доступний у серверній історії після reload.
- Через Settings UI повторно збережено ту саму назву з нормалізацією пробілів і HEX `#1e9e52` → `#1E9E52`. Вибір Ford Kuga · chroma автоматично підставив збережений HEX. Після reload назва й HEX лишилися. Семантичні значення наявних налаштувань не змінювалися.
- П'ять інтеграційних тестів налаштувань перевіряють використання власного PDF, відхилення несумісного PDF без втрати старого, durable PNG/маски, прострочення початкового upload-токена, render/chroma без повторного HEX, видалення шаблону без втрати історичного результату та auth.
- Reduced motion передбачено CSS; комплексний accessibility-аудит усіх станів не виконаний.

## Межі

- Типовий PDF має відповідати оригінальній 41-сторінковій SDS-структурі. Довільний PDF не є універсальним SDS-шаблоном.
- HEX зберігається окремо для кожної машини. Для постійного повторного використання власний PNG потрібно додати до бібліотеки, а не завантажувати щоразу як тимчасовий файл.
- Вбудовані машини видаляються зі списку з можливістю відновлення; власні PNG/маски видаляються з підтвердженням незворотності. Історичні результати зберігаються незалежно.
- Це локальна перевірка. Vercel deployment, реальні S3/R2/CORS та cloud runtime не перевірені; вимоги до релізу залишаються у `GOAL-AUDIT.md`.

Чинне ТЗ для наступного UI-проходу: `UI-BRIEF.md`. Старі CSS-файли лишилися у джерелах, але не підключаються.
