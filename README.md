# Content Workshop — SDS + HEX → PNG

Один вебсервіс: React/TypeScript UI, FastAPI backend, оригінальне ядро HexPh, порт SDS для Linux. Розгорнуто на https://content-work-shop.vercel.app із приватним Backblaze B2.

Доступ без пароля: `vercel.json` задає `APP_PUBLIC_ACCESS=true`. Кожен із посиланням може генерувати файли, бачити спільну історію, змінювати налаштування та видаляти шаблони. Це не приватне посилання й не захист від витрачання квоти. Bucket залишається приватним, ключі — лише на сервері; `SESSION_SECRET` потрібен для підписування файлових токенів. Для закритого режиму прибрати цей прапорець і встановити `APP_PASSWORD` від 16 символів.

**Git → Vercel:** [повна покрокова інструкція](docs/DEPLOY-VERCEL.md): чистий ZIP, приватний GitHub, R2 або B2 без картки, environment variables, CORS, lifecycle, перевірки та типові помилки. R2 має безкоштовну квоту, але потребує платіжного профілю. Vercel Hobby — тільки особисті некомерційні проєкти, не безкоштовний бізнес-продакшен.

## Можливості

- Напис номерного знака: бренд + код, лише код, лише бренд, власний текст або порожній номер; бренд редагується, код не додається до власного тексту. Можна залишити оригінальний напис. Автовписування й захист контурів збережені; налаштування входять до автозбереженого референса, фактичний вибраний текст — у звіт та історію.
- PNG: чотири вбудовані шаблони, власний PNG, маски кузова/маркера, пензель/гумка, chroma-key, область номера, бренд і код на номері з автоматичним вписуванням тексту в ширину та висоту виділення, імпорт CSV/JSON, metallic, LAB match/keep, згладжування, ΔE, прозорість, пакетна генерація, окремі PNG або ZIP із папками й звітом.
- SDS: оригінальний 41-сторінковий еталон, `{VALUE}`, `{CODE}`, `{COLOR}`, `{BRAND}`, точні назви, пакетні PDF, перевірка 24 зон назв, незмінності дат та решти тексту всіх сторінок.
- PDF-редактор: пошук, регістр, вибір сторінок, перший/усі збіги, заміна з підбором розміру шрифту та захистом сусіднього тексту.
- Редактор масок і області номера: колесо миші наближає/віддаляє фото навколо курсора; діапазон 10–1600% від масштабу вписування, кнопки «+», «−», «Вписати». Масштабування не змінює пікселі маски чи координати виділення в оригіналі.
- Відкритий доступ без входу, приватне object storage, реальний прогрес, зупинка після поточного файлу, попередній перегляд. Зміна форми не видаляє готові результати.
- LastWriteTime для PNG/SDS і PDF-редагування: початкова дата/час у `Europe/Kyiv`, крок у хвилинах або випадковий крок із діапазону; дати зберігаються в історії та застосовуються до файлів усередині ZIP.
- Серверна історія PNG, SDS і PDF-редагувань на 30 днів: один список генерації — один пакет, preview файлів, скачування всього пакета ZIP, пошук серед завантажених пакетів, фільтри та пагінація. Старі записи без `batch_id` лишаються окремими файлами. Мінімалістичний графітово-білий UI: темна/світла теми з анімованою хвилею, анімований перемикач Фото/SDS, компактні додаткові параметри та підтримка reduced motion.
- Налаштування: типовий шаблон назви SDS, постійний PDF-еталон, бібліотека до 100 власних машин (PNG і необов’язкові маски), видалення PDF та всіх машин, відновлення вбудованих шаблонів, збережений ключовий HEX для кожної машини. Після вибору машини HEX підставляється автоматично; без маски кузова генератор сам будує chroma-маску.

SDS-генератор змінює назву товару у наданому документі. Він не генерує хімічний склад або класифікацію небезпеки. Технічна перевірка збереження PDF не є перевіркою правильності вихідного SDS.

Відомий дефект вихідного еталона: на сторінці 9 частина основного тексту виходить за правий край. Піксельне порівняння підтвердило, що ця область збережена без змін. Виправлення верстки самого еталона — окреме завдання; поточний генератор його не виконує.

## Локальний запуск (Windows PowerShell)

Потрібні Python 3.12 і Node.js 22+.

```powershell
python -m venv .venv
.\.venv\Scripts\python -m pip install -r requirements-dev.txt
npm run install:frontend
npm run dev
```

Відкрити `http://127.0.0.1:5173`. API працює на `127.0.0.1:8000`. Процес стартує обидва сервери; Ctrl+C завершує їх. Без `.env` локальна версія використовує `tmp/storage` і не вимагає пароля. Сервер слухає лише loopback. У Linux створити `.venv` так само, для pip використовувати `.venv/bin/python`.

Щоб перевірити хмарне сховище локально, скопіювати `.env.example` в `.env.local`, заповнити значення та додати localhost origin до CORS bucket. Секрети не додавати у Git.

## Деплой на Vercel

Виконувати [docs/DEPLOY-VERCEL.md](docs/DEPLOY-VERCEL.md) по порядку. Усі актуальні значення env і окремі правила очищення R2/B2 описані там. Не застосовувати R2 lifecycle до B2 без адаптації: старі/приховані версії B2 продовжують займати місце.

Конфігурація: root `./`, preset `Other`, Python 3.12, Node 22, Fluid Compute, максимум одного API-запиту 300 секунд. Пам’ять Fluid не задається у `vercel.json`.

API розміщений у Frankfurt (`fra1`) поруч із європейським B2, а не у типовому Washington (`iad1`). PNG перефарбовує тільки області ненульових масок; результат і прев’ю паралельно записуються одразу у фінальну історію, без тимчасових копій. Перевірені піксельна тотожність попередньому алгоритму, feather/overlap/metallic, незмінність alpha та контурів. `Server-Timing` показує read/process/encode/upload/history/total, UI — фактичний час на фото, включно зі збереженням.

Без production-секрету або S3/R2 API закритий. Пароль потрібен лише із вимкненим `APP_PUBLIC_ACCESS`. `/tmp` не використовується як постійне сховище Vercel.

## Чистий пакет для Git

```powershell
.\.venv\Scripts\python tools/prepare_git.py --check
.\.venv\Scripts\python tools/prepare_git.py
```

Новий архів: `tmp/releases/content-workshop-git.zip`, з SHA256 manifest. Без секретів `.env`, залежностей, локального сховища, скриншотів і `.git`. Існуючий ZIP не перезаписується; для наступної версії задати `--output`. Це не commit, push або deployment. Обмежений пошук credential patterns не є повноцінним secret scanner.

`tools/check_cloud_storage.py` за замовчуванням перевіряє лише env без мережі; `--cloud` явно дозволяє тимчасові записи та signed upload 6 MiB. Цей тест не перевіряє browser CORS або Vercel runtime.

## Архітектурні обмеження

Вхідні PNG/PDF до 25 MiB; PNG до 8 млн пікселів, PDF до 200 сторінок. Усі надані шаблони 2048×2048 підтримуються. Списки до 200 елементів; кожен PNG/PDF обробляється окремим запитом. Тривалі background jobs не запускаються всередині serverless-функцій: вкладку треба залишати відкритою до завершення пакета.

Великі файли йдуть браузер → приватний bucket через короткочасний підписаний PUT. Генерація читає файл із bucket та записує результат туди; API повертає лише метадані/посилання. Так не перевищується [ліміт payload Vercel 4,5 МБ](https://vercel.com/docs/functions/limitations). [Python runtime](https://vercel.com/docs/functions/runtimes/python) підтримує ці залежності; включені тільки headless OpenCV та необхідні assets.

Посилання на скачування діють одну годину, файлові токени — 24 години. Історія видає нові посилання після повторного входу протягом 30 днів. Форма й незавершений прогрес лишаються в поточній вкладці; готові результати збережені на сервері. ZIP збирається в браузері до сумарних 250 MiB, понад це доступні окремі завантаження.

LastWriteTime зберігається в API як ISO datetime із часовим поясом (`last_written_at`), окремо від фактичного часу генерації та строку історії. ZIP містить київський локальний час для кожного PNG/PDF; DOS-формат ZIP підтримує роки 1980–2107 і має точність 2 секунди. `generation-report.json` зберігає ISO-дату та `timestamp_timezone: Europe/Kyiv`. При ввімкненому LastWriteTime навіть окремий файл завантажується в однофайловому ZIP. Після розпакування дата запису доступна програмі-архіватору; браузер не може встановити Windows LastWriteTime/CreationTime для прямого PNG/PDF-скачування. Дата самого ZIP визначається браузером/ОС. Стару вибрану дату не застосовуємо до серверного `mtime`: вона не скорочує 30-денний строк зберігання. SAM із GPU/моделлю не включений: для масок доступні ручний редактор/chroma в UI та flood/GrabCut через API.

Історія — окремі immutable JSON-записи та копії результатів/прев’ю у `history/`. Нові запити одного списку мають спільний UUID `batch_id`, позицію `batch_index` і заплановану кількість `batch_size`. Скасований/невдалий пакет зберігає вже завершені файли; UI показує фактичну кількість. Без `batch_id` старі записи не можна надійно віднести до списку: час генерації для цього не вгадується.

Пакети індексуються immutable membership-об’єктами з накопичувальним summary snapshot, без спільного перезаписуваного лічильника. Звичайна сторінка історії читає списки ключів і один snapshot на пакет, а не всі 200 manifest на кожен пакет. Snapshot використовується лише при точній відповідності всіх member IDs; за конкурентної/застарілої версії читаються оригінальні manifest. Деталі пакета видають усі файли, до 8 паралельних S3 GET. Це перевірено локально та SDK stubs, не виміряно в реальному bucket/Vercel.

Один пароль означає одну спільну бібліотеку власника, не мультитенантний сервіс. Історія не архівує вхідні PNG/PDF/маски. Власний PNG, завантажений прямо в генератор фото, після першої успішної генерації автоматично зберігається окремо в бібліотеці референсів разом із масками, ключовим HEX і конфігурацією номера. Він одразу доступний у списку машин та налаштуваннях, без повторного завантаження. Повторні кольори й повторне завантаження ідентичних PNG-байтів не створюють дублів і не перезаписують раніше збережені налаштування. Результати, створені до додавання історії, автоматично не імпортуються. Локальний adapter очищує прострочені файли під час старту. S3 операції [CopyObject і ListObjectsV2 підтримуються R2](https://developers.cloudflare.com/r2/api/s3/api/); живу хмарну інтеграцію ще потрібно перевірити.

## Перевірка

Налаштування відкриваються іконкою у верхній панелі (`#settings`). PDF перед встановленням перевіряється на сумісність із 41-сторінковою структурою; несумісний файл не замінює попередній. Видалення PDF залишає сервіс без типового еталона (`available:false`, `file:null`): генерація без явного PDF відхиляється, прихованого fallback немає. Вбудований PDF можна відновити окремою дією; власна durable-копія під час видалення/заміни фізично видаляється.

Вбудовані машини видаляються логічно: зникають із каталогу та недоступні для render за ID, але packaged assets зберігаються для відновлення. Власні машини видаляються разом із їхніми durable PNG/масками. Видалення джерела не видаляє історичні результати. Налаштування й власні PNG/маски зберігаються у `preferences/` та `library/` без автоматичного строку видалення; у JSON зберігаються описи об’єктів, не застаріваючі токени. Конфігурація розрахована на одного власника: одночасне збереження налаштувань із різних вкладок/інстансів Vercel може перезаписати попередню зміну; багатокористувацького контролю версій немає.

Перед окремим скачуванням або ZIP клієнт автоматично оновлює підписане посилання, поки токен файлу чинний. Це не подовжує строк зберігання об’єкта в bucket.

```powershell
.\.venv\Scripts\python -X utf8 -m pytest -q
npm run test:frontend
npm run build
npm --prefix frontend audit
```

Інтеграційні тести охоплюють повний PDF, піксельну незмінність сторінок varnish, пошук/заміну у згенерованому SDS, PNG/alpha/маски/ΔE, власний upload, парсер, auth, підроблені токени, production fail-closed, групування/пагінацію/часткові пакети, summary fast path і stale fallback, ISO-дати та видалення/відновлення шаблонів. Контурні регресії перевіряють відблиски, світлий кузов, вкладену білу панель, перспективу, нахил, EU-смугу та неточне виділення. S3 тести перевіряють підписані URL і контракти SDK без реального хмарного облікового запису; це не замінює перевірку пункту 6 після деплою.

Заміна номера використовує світлий внутрішній контур, а не весь виділений прямокутник. Старі літери стираються тільки всередині нього; насичені відблиски кузова, рамка та синя EU-смуга не входять у заливку. Якщо контур не визначено надійно, текст і фон номера не змінюються, результат містить попередження з проханням уточнити область. Саме виділення має охоплювати номер, а не всю машину.

## Файли

- `backend/` — API, auth/storage, PNG-адаптер, SDS і PDF-редактор.
- `frontend/` — базовий UI, браузерний редактор масок, ZIP.
- `assets/` — надані шаблони, PDF-еталон, вільно поширювані Noto Sans.
- `vendor/hexph/hexph/` — витягнутий код користувача, без переписування алгоритму LAB.
- `docs/UI-BRIEF.md` — ТЗ наступному дизайнеру/UI-агенту.
- `docs/DEPLOY-VERCEL.md` — повна інструкція Git → приватне сховище → Vercel.
- `docs/SOURCE-ANALYSIS.md` — аналіз джерел і таблиця перенесення можливостей.
- `docs/API.md` — контракт frontend/backend.
- `docs/VERIFICATION.md` — виконані перевірки, результати та неперевірені хмарні сценарії.
- `docs/GOAL-AUDIT.md` — чесна перевірка відповідності меті, ТЗ і release blockers.
- `docs/UI-REDESIGN.md` — перевірка актуального мінімалістичного дизайну та налаштувань.

EXE не запускаються і не постачаються серверу. Шрифти Windows у генераторах замінені на Noto Sans з OFL; через це геометрія тексту може трохи відрізнятися від desktop, але перевіряється його повнота й відсутність змін поза заданими зонами. UI використовує системні шрифти, без зовнішніх font-запитів.

PyMuPDF має AGPL/комерційну модель ліцензування ([офіційні умови](https://pymupdf.readthedocs.io/en/latest/about.html)). Перед розповсюдженням закритого сервісу третім особам треба визначити сумісний спосіб ліцензування. Це не враховано як оплачена комерційна ліцензія в цьому проєкті.
